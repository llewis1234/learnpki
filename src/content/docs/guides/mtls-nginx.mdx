In normal TLS only the server shows a certificate. With **mutual TLS (mTLS)** the client shows one too. The server refuses anyone whose certificate wasn't issued by a CA it trusts. It's a strong way to lock down APIs, internal services and device traffic.

<Diagram kind="mtls" />

You need the CA from [module 2](/guides/build-your-ca/) running before you start.

## 1. Issue a server certificate

Request a certificate for `localhost`. Enter the provisioner password when asked.

```sh title="terminal"
step ca certificate localhost server.crt server.key
```

```text title="Expected output"
✔ Provisioner: admin@example.com (JWK) [kid: UJJTomB6AaEpdfH578MY1o_S875zQEU3GG05pwaG11E]
✔ CA: https://localhost:9000
✔ Certificate: server.crt
✔ Private Key: server.key
```

## 2. Issue a client certificate

```sh title="terminal"
step ca certificate alice client.crt client.key
```

```text title="Expected output"
✔ Provisioner: admin@example.com (JWK) [kid: UJJTomB6AaEpdfH578MY1o_S875zQEU3GG05pwaG11E]
✔ CA: https://localhost:9000
✔ Certificate: client.crt
✔ Private Key: client.key
```

## 3. Copy the files for nginx

Copy the root certificate into your working folder:

```sh title="terminal"
cp $(step path)/certs/root_ca.crt .
```

Create a folder for nginx to read from:

```sh title="terminal"
sudo mkdir -p /etc/pki-fun
```

Copy the server certificate, server key and root into it:

```sh title="terminal"
sudo cp server.crt server.key root_ca.crt /etc/pki-fun/
```

## 4. Configure nginx

{/* UNVERIFIED: nginx config and the responses below have not been run against a live nginx yet. */}

```nginx title="/etc/nginx/conf.d/mtls.conf"
server {
    listen 8443 ssl;
    server_name localhost;

    ssl_certificate         /etc/pki-fun/server.crt;
    ssl_certificate_key     /etc/pki-fun/server.key;

    # Trust only client certs from our CA
    ssl_client_certificate  /etc/pki-fun/root_ca.crt;
    ssl_verify_client       on;
    ssl_verify_depth        2;

    location / {
        return 200 "Hello, $ssl_client_s_dn\n";
    }
}
```

:::tip[Why the root, not the intermediate?]
`step ca certificate` saves the leaf and the intermediate together in `client.crt`. Clients send both, so nginx only needs the root to complete the chain. `ssl_verify_depth 2` allows leaf → intermediate → root.
:::

Reload nginx to apply the config:

```sh title="terminal"
sudo nginx -s reload
```

## 5. Test it

Without a client certificate, nginx rejects you:

```sh title="terminal"
curl --cacert root_ca.crt https://localhost:8443
```

```text title="Expected output (excerpt)"
<html>
<head><title>400 No required SSL certificate was sent</title></head>
```

With one, you're in:

```sh title="terminal"
curl --cacert root_ca.crt \
  --cert client.crt --key client.key \
  https://localhost:8443
```

```text title="Expected output"
Hello, CN=alice
```

:::caution[Short certificates expire fast]
step-ca issues 24-hour certificates by default. If tests suddenly fail tomorrow, renew with `step ca renew client.crt client.key`.
:::
