In normal TLS only the server shows a certificate. With **mutual TLS (mTLS)** the client shows one too. The server refuses anyone whose certificate wasn't issued by a CA it trusts. It's a strong way to lock down APIs, internal services and device traffic.

<Diagram kind="mtls" />

:::note[Before you start]
Do [module 2](/guides/build-your-ca/) and [module 3](/guides/issue-and-inspect/) first.

- **Start your CA** in its own terminal and leave it running: `step-ca $(step path)/config/ca.json`. Enter the password you chose in module 2. If the CA is already running, skip this.
- **Open a second terminal** for the commands on this page.
- nginx is already running in the lab VM. This module adds a site on port 8443, so nothing else may use that port.
:::

Work in a new folder:

```sh title="terminal"
mkdir -p ~/pki-lab/mtls && cd ~/pki-lab/mtls
```

## 1. Issue a server certificate

Request a certificate for `localhost`. Enter the provisioner password when asked.

```sh title="terminal"
step ca certificate localhost server.crt server.key
```

```text title="Expected output"
✔ Provisioner: admin@example.com (JWK) [kid: g1zyOj-wl88rXBet9_rLLiMIvmqgERXB07sYMELbX4c]
✔ CA: https://localhost:9000
✔ Certificate: server.crt
✔ Private Key: server.key
```

## 2. Issue a client certificate

```sh title="terminal"
step ca certificate alice client.crt client.key
```

```text title="Expected output"
✔ Provisioner: admin@example.com (JWK) [kid: g1zyOj-wl88rXBet9_rLLiMIvmqgERXB07sYMELbX4c]
✔ CA: https://localhost:9000
✔ Certificate: client.crt
✔ Private Key: client.key
```

The default template gives every certificate both Server and Client Authentication, so this one works for mTLS as-is. [Module 5](/guides/eap-tls-freeradius/) shows how to make them stricter.

## 3. Copy the files for nginx

Copy the root certificate into your working folder:

```sh title="terminal"
cp $(step path)/certs/root_ca.crt .
```

Create a folder for nginx to read from:

```sh title="terminal"
sudo mkdir -p /etc/pki-lab
```

Copy the server certificate, server key and root into it:

```sh title="terminal"
sudo cp server.crt server.key root_ca.crt /etc/pki-lab/
```

## 4. Configure nginx

```nginx title="/etc/nginx/conf.d/mtls.conf"
server {
    listen 8443 ssl;
    server_name localhost;

    ssl_certificate         /etc/pki-lab/server.crt;
    ssl_certificate_key     /etc/pki-lab/server.key;

    # Trust only client certs from our CA
    ssl_client_certificate  /etc/pki-lab/root_ca.crt;
    ssl_verify_client       on;
    ssl_verify_depth        2;

    location / {
        return 200 "Hello, $ssl_client_s_dn\n";
    }
}
```

:::tip[Why the root, not the intermediate?]
`step ca certificate` saves the leaf and the intermediate together in `client.crt`. Clients send both, so nginx only needs the root to complete the chain. `ssl_verify_depth 2` allows leaf → intermediate → root.
:::

Check the config:

```sh title="terminal"
sudo nginx -t
```

```text title="Expected output"
nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
nginx: configuration file /etc/nginx/nginx.conf test is successful
```

Reload nginx to apply the config:

```sh title="terminal"
sudo nginx -s reload
```

On macOS with Homebrew, the config folder is `$(brew --prefix)/etc/nginx/servers/` and you don't need `sudo`.

## 5. Test it

Without a client certificate, nginx rejects you:

```sh title="terminal"
curl --cacert root_ca.crt https://localhost:8443
```

```text title="Expected output (excerpt)"
<html>
<head><title>400 No required SSL certificate was sent</title></head>
```

With one, you're in:

```sh title="terminal"
curl --cacert root_ca.crt \
  --cert client.crt --key client.key \
  https://localhost:8443
```

```text title="Expected output"
Hello, CN=alice
```

`$ssl_client_s_dn` is the client certificate's subject. A real app uses it, or the SAN, to decide what this client may do.

## Break it

### A client certificate with no intermediate

Make a copy of the client certificate with only the leaf:

```sh title="terminal"
awk '/BEGIN/{n++} n==1' client.crt > client-leaf.crt
```

```sh title="terminal"
curl --cacert root_ca.crt \
  --cert client-leaf.crt --key client.key \
  https://localhost:8443
```

```text title="Expected output (excerpt)"
<html>
<head><title>400 The SSL certificate error</title></head>
```

nginx has only the root. Without the intermediate, it can't build the chain. This proves the tip above: the client must send the bundle.

### A client certificate from another CA

Any certificate from a CA that nginx doesn't trust gets the same answer. If you made a second test CA, issue a client certificate from it as `other.crt` and `other.key`, then try it:

```sh title="terminal"
curl --cacert root_ca.crt \
  --cert other.crt --key other.key \
  https://localhost:8443
```

```text title="Expected output (excerpt)"
<html>
<head><title>400 The SSL certificate error</title></head>
```

To see the exact reason, raise the log level. Add `error_log /var/log/nginx/error.log info;` inside the `server` block and reload. Repeat both tests, then read the log:

```sh title="terminal"
sudo grep "client SSL certificate verify" /var/log/nginx/error.log
```

```text title="Expected output (excerpt)"
[info] 7616#7616: *5 client SSL certificate verify error: (21:unable to verify the first certificate) while reading client request headers, client: 127.0.0.1, server: localhost ...
[info] 7618#7618: *6 client SSL certificate verify error: (20:unable to get local issuer certificate) while reading client request headers, client: 127.0.0.1, server: localhost ...
```

The numbers are OpenSSL error codes. [Module 6](/guides/operations/) has a table of the common ones.

:::caution[Short certificates expire fast]
step-ca issues 24-hour certificates by default. If tests suddenly fail tomorrow, renew with `step ca renew client.crt client.key`. [Module 6](/guides/operations/) automates this.
:::

## Clean up

nginx serves the lab site on port 8443 until you remove it. Do this in the lab VM too.

Remove the lab config:

```sh title="terminal"
sudo rm /etc/nginx/conf.d/mtls.conf
```

Reload nginx:

```sh title="terminal"
sudo nginx -s reload
```

Remove the copied certificate and key:

```sh title="terminal"
sudo rm -r /etc/pki-lab
```

Your certificates stay in `~/pki-lab/mtls`.
